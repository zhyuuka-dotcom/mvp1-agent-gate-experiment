§4 MVP-2 预注册 v0.2 冻结稿（补发全文，冻结生效）
版本：v0.2-frozen | 冻结日期：2026-10-10 | 外审：ChatGPT-5.2 三轮复核无异议 | 实施授权：另发（终报签收后）
S1 研究问题：独立完成验收（DONE 门/终态审计）能否改善最终交付质量？发现效果与交付效果分解测量。挑战集结论不得外推为日常发生率；假完成自然发生率、计划门禁价值（待文件层约束修复）、模型差异、规格清晰度线不在本轮范围。
S2 预算模型（三计数器，冻结）：
• N = 30 工作轮：首次完成阶段可用；
• M = 5 修复轮：仅可在收到失败反馈后使用；M 耗尽→不再启动修复，未过验收 = failed-unverified；
• F = 5 反馈事件：每次携带协议信息的验收失败反馈扣 1；F 耗尽→固定回执（预冻结文本："验收未通过，诊断反馈额度已用尽；最终状态依实际验收结果判定"，零动态信息：不含失败计数/类别/观测值/路径/堆栈；内容不随隐藏失败情况变化，入执行器测试）；
• 总轮硬上限 = N + M = 35（派生）；T=0 为唯一硬终止；
• audit-error 三不：不扣 N/M/F、不计 agent 失败、统计分母单列；
• 四组总预算口径一致（各臂 N+M+F 相同；A 臂无门禁故 M/F 自然闲置，总轮次上限相同）。
S3 反馈协议 v1（双路径，冻结）：
• 披露许可线 = 要求是否对 agent 明示（以运行前冻结的 agent 可见任务文本为准：规格+验收例+明示约束），与"测试是否隐藏"脱钩；
• 明示项路径：反馈模板冻结 + 白名单字段结构化填充（执行器只有填格权、无诊断生成权）；
• 隐藏项路径：零运行时生成——反馈串/句柄全部预写随神谕冻结，运行时仅选择，禁止任何插值填空；句柄 EC-k 不透明（ID→类别对照表冻结入档，ID→要求映射不存在于 agent 可见物）；运行时选择规则（顺序、去重、组合）预冻结；
• 每 EC 动态失败计数移出 agent 可见反馈（入内部遥测）；单次披露范围 = 全部失败类别（刻意设计，测类别提示引导推断未明示要求的能力）；
• 反馈生成器/sanitizer 独立验证（种子失败注入验证类别映射；泄漏性质测试）；恢复率报告必须注明反馈协议与 F/M 消耗。
S4 设计 2×2：
臂	DONE 门	终态审计+修复
A	关	关
B	开	关
C	关	开
D	开	开
• "关" = 不暴露不阻断不修复，仍离线测量；终态审计"开"含开局告知（mechanics 明示审计机制与 M/F 额度）；
• 估计目标：四种完整治理策略的端到端效果（含共享 F 竞争），非单机制纯因果；机制分解由第二轮消融臂 B′（同 N/M/F 无门禁）/ C′（无审计）承担；共享 F 竞争登记为设计特征；
• 全臂结束用同一冻结验收版离线评分。
S5 任务与校准（冻结）：
• 第一层：T2 任务 A vs B，n=5/臂——管线验证+行为连续性核查；零失败如实记界（0/5 单侧 95% 上界 ≤45.1%，且仅当分母确为 5 次有效观测），不得解释为门禁有效；
• 第二层：挑战集 2×2，n=20/臂；
• 校准：裸 A 基线、固定模型配置与预算、校准样本 n=10 冻结；双带联合判据：DONE 产出率 ∈ [50%, 80%]（分母 = 全部有效校准运行）∧ 首验失败率 ∈ [30%, 70%]（分母 = 出现首次 DONE 的运行；无 DONE 的运行不计入"低于 30%"）；
• 更换规则：带外→按预冻结候选清单更替任务→新校准轮（n=10 重跑）；禁止无限重复至偶然合意；全部校准运行与更换记录留档、不得用于正式效果估计；校准与正式样本严格分离，正式样本冻结点 = 双带命中后的 commit；
• 双带是任务选择标准，非门禁有效性证据。
S6 指标（分子/分母/遥测字段预冻结，规格表随实施包交付）：首验失效率（主指标 = 每运行首次 DONE）、错误交付率（终态 failed-unverified / 全部运行）、恢复率（分母 = 收到失败反馈且 M 有剩余的运行，audit-error 排除）、无声明完成率（分母 = 终态验收通过运行）、成本（轮/token/API 成本/验收开销/反馈事件数分列）。发现效果与交付效果分开报告；按 cell 报告、禁跨异质条件池化；小样本用二项精确界。
交付三态：verified ≡ 通过冻结验收套件（≠ 满足全部规格；覆盖缺口注记随结果披露）/ failed-unverified / audit-error。验收失败 ≠ agent 不诚实；验收通过 ≠ 规格全覆盖。
S7 执行器诚实性（冻结清单）：实发文本/真实预算/工具执行完整性/机器可读原因码/验收器版本与自身验证记录，全部冻结存档；MULTI_REQ 条款（本文件 §2.4：单步执行 + 回执原因码列明全部请求及处置 + 丢弃请求全文入遥测）；覆盖表冻结为研究工件、不对 agent 可见。
S8 实施项清单（可行性+成本评估随下次回执）：F/M/N 计数器与状态机、固定回执注入、白名单填充模板、隐藏语料注入、MULTI_REQ 检测与原因码、audit-error 分支、覆盖表工件、指标遥测字段、双带校准脚手架。
