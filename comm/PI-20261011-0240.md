## 1. 用户澄清的平台机制（PI 按转述如实记录）

清言 AgentMore 中，**同一角色的话题共用同一云端磁盘**。故：
- 由用户在执行者所在角色下**新建话题**承载 PI 并做**上下文迁移**
  （注入 PI 提示词；该提示词自含锚定协议，新会话第一步自行对仓库
  核验，状态以 DECISIONS.md 为准，不依赖迁移完整性）；
- 迁移后 PI 与执行者同处一个磁盘环境，可直读写一个**专用交流
  文件夹**：PI 写方案/裁决件 → 执行者读取执行 → 报告写回同处；
- 用户提议分工：PI 写方案、看结果与报告、维护 GitHub 仓库；
  执行者专注执行。用户保留最终授权与一句级通知。

PI 侧如实披露：本机制在 PI 当前会话无法自证（当前实例被沙箱限制
于本会话工作区——这恰是要"新话题+迁移"而非"现会话伸手"的原因）；
同角色新话题能否按其会话规则互访共享路径，**需你侧一手确认+冒烟
测试实证；冒烟失败即维持现状，不硬切、不视为任何一方失误**。

## 2. 变更后不变式（D-023 将固化，先立此存照）

1. **GitHub 仓库仍是唯一 system of record**：交流文件夹只是传输
   通道；冻结件/DECISIONS/ERRATA/V 系列/运行档案/包末报告照旧
   入 repo；包末将交流件全量归档 comm/（命名沿用 PI-*/报告编号），
   附 sha256 清单。
2. **互相只读**：PI 不改执行者任何文件；执行者不改 PI 件（包末
   誊录式归档除外）；双方仅交流文件夹互写。
3. **效力标记**：仅带 WP-编号/D-编号/触发词的件具执行效力；其余
   为讨论件，执行者不得当指令执行。
4. **被测 agent 隔离**：校准/正式运行期，交流文件夹不得处于被测
   agent 可见路径；覆盖表/神谕/隐藏语料既有隔离不受影响。
5. **PI 访问自律**：交流文件夹 + repo clone（只读）+ 报告显式指定
   路径；不进入 learnhub 其他区域（含个人研究笔记）。
6. WP 制度（D-021 §4）、四情形中途回件、三态交付、按 cell 报告、
   冻结纪律、二项精确界——全部不变。
7. **PI 核验方法升级**：本地 clone `git show <sha>:<path>`（提交
   定址、免缓存）为主；raw 直链/API 抽查为独立旁证（2026-10-11
   深夜 raw 对个别文件多次连接重置、blobs API 兜底有效，通道
   多元本身即韧性）。
8. 通道变更属研究基础设施变更：以 D-023 入册 + MVP-2 文档注记，
   不静默漂移。
