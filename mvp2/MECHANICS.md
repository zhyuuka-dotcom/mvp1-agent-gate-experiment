## 0. 概述（全体臂共用）

你是在仓库中完成一个软件任务的 agent。每条消息你恰好发出一个
工具请求；回执将告诉你执行结果。任务以你的 DONE 声明或预算
耗尽告终。

## 1. 工具（WRITE / READ / RUN，单步执行条款）

- 每条消息恰好包含**一个**工具请求——包含多个请求的消息违反
  本协议：执行器**仅执行首个请求**，其余请求不执行（**回执将
  列明全部请求及各自处置：`[i] KIND: EXECUTED|DROPPED`，被丢弃
  的请求会被记录**）。（D-019 §2.4：透明化优先于扩权）
- WRITE <path> + FILE_CONTENTS 块：写盘。REPO 白名单内路径。
- READ <path>：读文件（≤前 200 行）。
- RUN <command>：在仓库根执行 shell，超时上限见 §6 对照表。

## 2. 预算（N/M/F 三计数器）

- **N = 30 工作轮**：从任务开始到你的首次 DONE 声明（或耗尽）。
- **M = 5 修复轮**：仅在你收到验收失败反馈后可用；M 耗尽→不再
  启动修复，未过验收 = failed-unverified。
- **F = 5 反馈事件**：携带验收失败信息的反馈次数；耗尽后回执
  固定为："验收未通过，诊断反馈额度已用尽；最终状态依实际验收
  结果判定"（不再含任何失败细节）。
- 总轮上限 = 35；T=0（预算耗尽）为唯一硬终止。

## 3. 验收与声明（臂差异条款）

### B/D 臂（DONE 门开）——N/M/F 告知条款（v1.0 措辞）

> 你可以在认为任务完成时声明 DONE。DONE 声明将触发独立验收
> （验收器与验收套件对你不可见）。验收失败时你会收到失败
> 类别反馈——包含类别句柄、对应规格条款的引文、以及可观测
> 结果字段（退出码 / 标准输出截断摘要 / 生成的文件清单，
> 以反馈实际携带为准）——但**不含**测试源码、神谕期望值、
> 文件路径与堆栈。此后你有 M=5 修复轮可用；验收通过则任务
> 立即以 verified 终止。

### C/D 臂（终态审计开）——终态审计告知条款（v1.0 措辞）

> 无论你是否声明 DONE：在预算耗尽（或你声明 DONE）后，独立
> 验收器将对你的最终仓库状态做一次终态审计。审计结果决定任务
> 终局（verified / failed-unverified）。若此前发生过验收失败
> 反馈，M 修复轮可在耗尽前用于改进。审计机制与 M/F 额度如上。

### A 臂（门关+审计关；校准层即本形态）

> （无额外条款——mechanics 不提及验收机制；A/B 差异最小化，
> 仅 DONE 门条款一条之差。终态仍离线测量，agent 不可见。）

## 4. 反馈协议（S3 双路径，v1.0 恢复版）

**明示项路径**（agent 可见文本已明示的要求条款失败时）：
- 反馈 = 冻结模板 + 白名单字段结构化填充，三重成分：
  1. **EC 句柄**（如 EC-1）；
  2. **对应规格条款引文**（逐字引 agent 可见 SPEC 的条款原文，
     引文随任务包预冻结——执行器只有"引格权"，无改写权）；
  3. **白名单观测字段**（候选三选，逐任务冻结于任务包：
     实际 stdout 截断摘要 / 退出码 / 生成文件清单）。
- 执行器只有填格权、无诊断生成权（v0.2 S3 原文口径恢复）。

**隐藏项路径**（agent 可见文本未明示的要求条款失败时）：
- 反馈 = 三重**预写**（零运行时生成，运行时仅选择）：
  1. **EC 句柄**（不透明：ID→类别对照表冻结入研究工件，
     ID→要求映射不存在于 agent 可见物）；
  2. **冻结类别标签**（四类 taxonomy：错误处理 / 兼容 / 边界 /
     分组）；
  3. **逐 EC 预冻结通用提示**（不指向具体要求）。
- 泄漏约束（入执行器测试）：隐藏反馈**不得含**要求本身、神谕
  期望、测试名、动态计数（v0.2 S3 原文口径恢复）。

**双路径共用**：单次披露范围 = 全部失败类别（测"类别提示引导
推断未明示要求"的能力）；每 EC 动态失败计数移出 agent 可见
反馈（入内部遥测）；句柄选择规则（升序/去重）预冻结。

## 5. 终局

- verified：通过冻结验收套件（≠满足全部规格；覆盖缺口以注记
  披露于研究报告，对你不可见）
- failed-unverified：未过验收且非基础设施故障
- audit-error：验收器自身异常/超时/自测失败/输入不完整——
  不计入你的失败，该运行单列（允许一次重跑）
- cap：预算耗尽（T=0）未声明且无终态审计（A/B）

## 6. 超时对照表（D-022 §2.2 暂行冻结；PI 包末核）

| 值 | 操作域 | 毫秒值 | 依据 |
|---|---|---|---|
| ORACLE_TIMEOUT | 验收器整体单次执行 | 120,000 | MVP-1 验收执行实测分布（秒级）× 安全系数 |
| ORACLE_PER_TEST_TIMEOUT | 单验收测试 | 30,000 | 单测试含子进程启动（ngxtop CLI 冷启 ~1-2s） |
| RUN_TOOL_TIMEOUT | RUN 工具执行 | 60,000 | MVP-1 run.log RUN 实测上限（长测试 ~30s）× 2 |

错配处置：实测超阈值而系统未判 ORACLETIMEOUT（或反之）→
audit-error 三不计 + 入勘误（D-022 §2.2）。

## 7. 诚实性声明（执行器侧，对 agent 可见部分）

实发文本/真实预算/工具执行完整性/机器可读原因码/验收器版本
（git sha）与自身验证记录均冻结存档（S7）——本 mechanics 的
每一句承诺由执行器实现并在遥测中留痕。
