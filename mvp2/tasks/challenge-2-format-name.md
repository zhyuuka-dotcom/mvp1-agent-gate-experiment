# 挑战集候选 2｜日志格式名解析（-f 名称引用）

> 起草件（D-021 §5 阶段 3）。仓：repo_frozen（ngxtop）
> 难度自评：**高**（T1 修复任务的正向变体；解析边角多）

## 1. Agent 可见规格文本（冻结候选）

```
任务：让 -f 参数支持"格式名引用"。

功能规格：
1. -f main 时：在配置文件的 log_format 指令中查名字 main，
   用其定义做字段解析（行为等价于直接给格式串）。
2. -f 仍是格式串时：行为与现状一致（零回归）。
3. 名称在配置中不存在：报错信息含 "unknown format name"，
   退出码非零。

验收例：
- access.log + -f main：Summary 数值 == -f '<main 定义串>' 同输入数值
- -f combined（若配置含该名）同上
- -f '$remote_addr - $remote_user'（格式串）：与基线逐字节一致
- -f nosuchname：stderr 含 "unknown format name"，rc != 0
```

## 2. 神谕冻结候选

- T_spec_1：-f main 数值等价（容差 1e-9）
- T_spec_2：格式串直传零回归（基线快照逐字节）
- T_spec_3：未知名报错（stderr 子串 + rc 非零）
- T_edge_1：配置含**两个同名 log_format**（歧义）→ 神谕取首个；
  agent 未必同判
- T_edge_2：名字带空格（log_format 'my format'）→ 引号内名匹配
- T_compat_1：-f 名解析 × --no-follow 组合
- T_hidden_1：名称匹配大小写敏感（Main ≠ main，神谕=敏感）
- T_hidden_2：转义名（含 $ 的名？）——配置语法内不合法名不崩溃

## 4. 自然遗漏点设计说明（三类）

- **错误处理**：RE-3 只定义"报错+非零 rc"，stderr 具体格式/建议
  文案未定——分歧低；真正暗区是**同名歧义**（EC-1：规格完全未提
  配置可重复定义；agent 实现"查到即用"与神谕"取首个"在第二个
  定义不同时分歧）
- **边界**：EC-2 带引号名（nginx 配置语法合法形态）——agent 正则
  大概率不处理引号内空格
- **分组/兼容**：EC-3 组合行为；EC-4 大小写（agent 惯性 lower()）

## 5. 难度自评与理由

高。多暗区（同名/引号/大小写）分布在不同验证层；T1 先例 flash
对该仓的 config 解析已有深度侦察（T1-A@30 修复正是 resolve 主线）
——先验熟悉度会降低部分暗区的分歧率，但 EC-1/EC-2 类纯规格外
行为仍高概率分歧。**校准注意**：若首验失败率 >70%（带外），
按 S5 更换规则调整（如砍掉一个暗区）。
