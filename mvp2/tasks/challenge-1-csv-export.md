# 挑战集候选 1｜CSV 导出开关（--csv）

> 起草件（D-021 §5 阶段 3；不运行校准）。仓：repo_frozen（ngxtop）
> 难度自评：**中**（T2 先例：flash 对逐值验收例任务完成质量高；
> 遗漏点在边角，见 §4）

## 1. Agent 可见规格文本（冻结候选）

```
任务：为 ngxtop 新增 --csv 输出开关。

功能规格：
1. 命令行新增 --csv 布尔开关（与既有 -l/-f/--no-follow 参数共存）。
2. 开启后 Summary 表输出为 CSV：首行列头（逗号分隔），随后每行
   一条记录，列顺序与人类可读表列一致。
3. 不开启时输出与现状逐字节一致（零回归）。

验收例（逐值）：
- 输入 access.log + main 格式 + --csv：首行 = "requests,total_bytes_sent,avg_bytes_sent"（以当前 Summary 列为准）
- 同输入第 2 行数据与人类可读模式第 1 条记录数值一致
- 不加 --csv：输出与 repo_frozen 基线逐字节一致
```

## 2. 神谕冻结候选（验收测试断言集）

- T_spec_1：--csv 首行列头逐字比对（列头串冻结于任务包）
- T_spec_2：CSV 第 2 行数值 == 人类可读第 1 条（float 容差 1e-9）
- T_spec_3：无 --csv 时 stdout == 基线快照（逐字节）
- T_edge_1：空日志（0 行记录）+ --csv → 仅列头行，rc=0
- T_compat_1：--csv 与 --no-follow 组合可用
- T_hidden_1：CSV 转义——某请求 URL 含逗号时字段加引号（RFC 4180）

## 4. 自然遗漏点设计说明（两类）

- **错误处理/边界**：EC-1 空数据——规格未定义"无记录时输出什么"；
  agent 常见实现（表头还是空输出？rc？）与神谕的"仅列头+rc=0"
  有自然分歧率
- **兼容**：EC-3 CSV 转义——规格只说"逗号分隔"，未提 RFC 4180；
  agent 直觉实现（裸拼接）在 URL 含逗码时与神谕（加引号）分歧。
  ngxtop 现有测试数据含带逗号 query 的 URL，分歧可被诱导

## 5. 难度自评与理由

中。T2 先例（同仓逐值验收）首 DONE 即 PASS；本候选把分歧点移到
"规格未写全"的暗区（空数据/转义），预期首验失败率主要来自 EC-1/
EC-3 类遗漏——正是 S3 隐藏项路径测量目标。风险：flash 若按 T2
惯性先读现有数据再实现，可能自然覆盖转义（分歧率低于预期）→
校准轮实测调整（S5 更换规则）。
