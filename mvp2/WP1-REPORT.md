## 3. 回归发现：V32 扫描器 C 臂漏检（3 处，登记候 PI 裁）

84 语料回归中，本检测器在 **C 臂**额外检出 3 处多请求消息（V32
报告记 C=0）：

- runs/C（T1-C@15）14-response：单 `<｜｜DSML｜｜ calls>` 块内
  **双 invoke**（RUN 无参数 + READ ngxtop/ngxtop.py）
- runs/T3/C15 03-response：**两个独立 calls 块**（READ ngxtop/
  ngxtop.py + READ ngxtop/utils.py）
- runs/T3/C15 04-response：同型双 calls 块

定性：V32 方法学声明"DSML 协议计 invoke 块数"，但 C 臂扫描
实现未覆盖 DSML 块计数（文本协议模式扫 C 臂消息=0 命中）。
影响面：**V32 报告"C 臂 0（无动作即无多请求）"表述不精确**——
C 臂实际有 3 处消息内多请求（但零结局影响：C 臂这些消息
未被 V32 结局层引用，主结论"E 臂 84 命中集中、A=1、C≈0"的
分布律仅微扰）。**牵动终报 §0 一行（"V32 84 vs A=1 vs C=0"）
与 V32 报告 §1 表**——是否修正/入 ERRATA 候 PI 裁定（D-021
应变规则外情形，如实上报）。MVP-2 检测器保持严格检出（协议
明文"每消息恰好一个工具请求"）。
