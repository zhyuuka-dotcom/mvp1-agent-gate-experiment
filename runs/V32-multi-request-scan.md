## 2. 命中的三型（事实分类）

**型一：流水叙事型枚举（E 臂主体，~82 处）**——模型在单条生成里按
"探索叙事"连写多个 READ/RUN（极值=T2-E@30 T1：64 个模式/255 行，
逐文件"READ X/继续叙述"）。执行器按选择规则执行一个（READ 取末、
RUN 取末），回执单结果，模型下一轮适应。**无直接结局改变证据**，
但构成 E 臂轮次经济学的隐性税（模型世界模型=批量执行，现实=单步）。

**型二：计划遮蔽（计划提交轮含内嵌 WRITE/RUN，≥6 处）**——E 臂
提交合同时把计划写成 "WRITE PLAN.md" 内嵌请求（T3-E@30 T10 亦含
RUN 检索）；执行器计划分支优先 → 内嵌请求一律不执行、回执不提。
实际无害：计划门禁自身将提交文本落盘 PLAN.md（终态 diff 的
"Only in repo: PLAN.md" 即门禁所写，非模型 WRITE 所写）。

**型三：双写（≥2 个 WRITE，全 18 次运行仅 2 处）**：
- **T3-E@30 T28**（WRITE tests/test_median.py ×2）：错版首匹配执行、
  修正版静默丢弃 → 假失败。**唯一结局改变案例，D-018 已裁**（三方
  事故链）
- T2-E@30 T7（WRITE PLAN.md ×2）：属型二计划遮蔽（回执=PLAN_REJECTED
  a5，两 WRITE 均未执行、门禁自落盘）——无结局影响

另：T3-E@30 T30 双 RUN（同一命令重复，末匹配执行其一，rc=1）。

## 3. 执行选择规则对账（run.log 权威）

WRITE=首匹配、READ=末匹配、RUN=末匹配、计划分支优先于一切工具
请求——扫描 84+ 命中逐条对账，无一例外。
